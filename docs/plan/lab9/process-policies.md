# ЛЗ9 — спринт тақтасының саясаты (ұсынылатын баптау)

> Бұл құжат — GitHub Projects-та **орындалды** деген дәлел емес. Тақта нақты бапталған соң оның URL-сын және статус ауысу тарихын қосу керек.

## Статустардың кіру және шығу саясаты

| Статус | Кіру шарты | Шығу шарты |
|---|---|---|
| Backlog | Тапсырма немесе тәуекел тіркелді | Мақсат, басымдық, иесі анықталды |
| Ready | DoR орындалды, қабылдау критерийі жазылды | Орындаушы мен WIP лимиті бойынша жұмыс басталды |
| In progress | Жұмыс нақты басталды, күн/уақыт тіркелді | Код/құжат және тексеруге сілтеме дайын |
| Review | Екінші тексерушіге жұмыс берілді | DoD орындалса Done; ақау болса In progress |
| Blocked | Нақты кедергі, оның иесі мен күні көрсетілді | Кедергі жойылып, келесі статусқа ауысты |
| Done | Қабылдау дәлелі тіркелген, DoD толық орындалған | Жаңа ақау жеке Issue болып ашылады |

**WIP лимиті:** әр адамға In progress ≤ 2, барлық команда бойынша Review ≤ 3. Статус сол күні ауыстырылып, ауысу уақыты журналға жазылады. Blocked тапсырма ескерусіз қалмайды.

## DoR (Definition of Ready)
- Қолданушыға немесе тапсыру нәтижесіне нақты пайдасы көрсетілген.
- Позитив және негатив қабылдау шарттары жазылған.
- Тапсырма 1–2 жұмыс күнінде орындалатын шағын көлемге бөлінген.
- Жауапты адам, тәуелділік және тексерілетін нәтиже анық.
- SEC-01/#2, SEC-02/#3, SEC-03/#4 бойынша мәселелер автоматты жабылды деп есептелмейді.

## DoD (Definition of Done)
- Қабылдау критерийі тестпен не құжатпен расталған.
- Код болса тиісті тест іске қосылған; құжат болса сілтемелер тексерілген.
- Екінші адам review жүргізіп, оның дәлелі сақталған.
- Стендке әсер етсе, стендте тексерілген немесе тексерілмегені ашық жазылған.
- README және Issue/PR сілтемелері жаңартылған.
- Қауіпсіздік бойынша критикалық ашық мәселе болса Done қойылмайды.

## Спринт мақсаттары — модель
- **Спринт 1 (12–16.10.2026):** пайдаланушының кіру → тест → нәтиже сценарийіне арналған қабылдау дәлелдерін дайындауға және 7/28 күн алшақтығын тіркеуге бағытталған модель.
- **Спринт 2 (19–23.10.2026):** тест/жоспар/AI қабылдау тексерулерінің review ағынын жеделдетуге бағытталған модель.

## Метрика анықтамалары
- Throughput: бес жұмыс күніндегі Done тапсырмалары.
- Cycle time: In progress → Done, жұмыс күні (8 сағ).
- p85: уақыт мәндерінің инклюзивті сызықтық интерполяциядағы 85-перцентилі.
- WIP: In progress + Review. Күндік WIP: 09:00–17:00 аралығындағы уақыт бойынша орташа.
- Little заңы: орташа WIP ≈ (Done/5 күн) × орташа cycle time.

Нақты тақтаға өткен соң: GitHub Projects → Board → Iteration, Status, Owner, Size өрістерін қосу; ауысуларды уақыт белгісімен тіркеу; CSV экспортын алып, симуляция орнына енгізу.
